# Kinshore Bay — Telegram bot

Портфолио-бот для вымышленного комплекса: рассказ о территории, карточки апартаментов, FAQ и подбор по датам через календарь, гостям и бюджету за ночь. Заезд выбирается в пределах 730 дней, поездка — до 90 ночей. Интерфейс — на английском, цены — демонстрационные и указаны в евро. Реальных бронирований, платежей, проверки доступности и сбора контактных данных нет.

## Посмотреть без Telegram

В PowerShell из корня проекта:

```powershell
python bot/bot.py --demo
```

Чтобы посмотреть главное меню с кнопкой Mini App на примере адреса-заглушки:

```powershell
python bot/bot.py --demo-mini-app
```

Чтобы посмотреть пример подтверждения и отправки демо-заявки без сети и без настоящего CRM-сервера:

```powershell
python bot/bot.py --demo-crm
```

В этом просмотре ответ CRM подменяется: он не создаёт заявку в базе.

Проверить сценарии:

```powershell
python -m unittest discover -s bot -p 'test_*.py'
```

## Запустить в Telegram

1. Создать нового бота в [@BotFather](https://t.me/BotFather) или выбрать своего тестового бота. Избегайте запуска одновременно с другим приложением для того же бота: используется long polling.
2. В PowerShell из корня проекта запустить команду ниже. При первом запуске ввести токен после приглашения: ввод скрыт, в команду его вставлять не нужно. Скрипт сохранит токен в локальном `bot/.env`, поэтому в следующий раз вводить его не понадобится. Не отправляйте токен в чат и не показывайте на скриншотах.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\bot\start.ps1
```

3. Открыть бота в Telegram и отправить `/start`. Остановить процесс — `Ctrl+C`. Если задана переменная окружения `BOT_TOKEN`, она имеет приоритет над файлом.

Файл `bot/.env` содержит токен в открытом виде и исключён из Git через `.gitignore`. Не отправляйте его вместе с проектом и не публикуйте. Если токен нужно заменить, удалите или измените этот файл локально; при удалении скрипт запросит токен при следующем запуске. Если файл уже существует, скрипт не перезаписывает его.

## Подключить Mini App

Когда приложение будет опубликовано по доступному HTTPS-адресу, добавьте в существующий `bot/.env` отдельную строку, не изменяя `BOT_TOKEN`:

```dotenv
MINI_APP_URL=https://example.com/site/miniapp.html
```

Это пример: замените адрес реальным HTTPS-адресом страницы приложения. Перезапустите бота и отправьте `/start`: над меню появится кнопка **Open Mini App**. Если переменная не задана, кнопка скрыта, а остальные функции бота работают как прежде. Переменная окружения `MINI_APP_URL` имеет приоритет над файлом. Бот проверяет формат HTTPS-адреса, но не его доступность и не соответствие опубликованному приложению.

У действующего [@KinshoreBay_app](https://t.me/KinshoreBay_app) кнопка **Open Mini App** доступна в главном меню бота и в меню чата. Она открывает [публичный гостевой подбор](https://kinshore-bay.scalo.biz/site/miniapp.html) с собственной демо-сессией. Заявки и черновики из чата хранятся в закрытом превью. Общая история потребует отдельной связи с учётной записью Telegram и серверной проверки `initData`. [Порядок настройки на VPS](../deploy/README.md#open-the-public-mini-app-from-telegram)

## Подключить демо-заявки к CRM

Связка отключена по умолчанию. После настройки CRM можно добавить в существующий `bot/.env` оба параметра: `CRM_API_URL` — HTTPS-адрес служебного endpoint, `CRM_API_TOKEN` — отдельный секрет CRM. Он должен совпадать с `KINSHORE_CRM_TOKEN` на стороне CRM и не должен быть токеном Telegram. Для локального теста допускается HTTP только на `127.0.0.1` или `::1`. Если задан только один параметр или они имеют неверный формат, бот не запустится с этой конфигурацией.

В подключённом режиме после подбора по датам, гостям и бюджету можно выбрать категорию апартаментов, проверить данные и нажать `Send demo request`. По кнопке **Children, pet & parking** можно указать число детей до 18 лет, питомца и приезд на машине. После первой попытки отправки эти ответы сохраняются для повтора с тем же ключом. CRM получает выбранную категорию, даты, число гостей, тариф и указанные ответы. Сервер проверяет цену и подбирает свободный демо-апартамент выбранной категории. Гость получает номер заявки.

При неопределённом результате `/resume` восстанавливает сохранённую заявку и позволяет повторить отправку с тем же ключом. На VPS проверены получение обновлений Telegram и отправка с повтором из контейнера бота в CRM. Настройка принимающего API описана в [инструкции CRM](../crm/README.md).

Для автономной работы на VPS предусмотрен [сервис Docker Compose](../deploy/README.md#telegram-bot) с автоперезапуском. Выбор дат в незавершённом диалоге хранится в памяти. Выбранная демо-заявка восстанавливается через `/resume` из отдельного тома. Для long polling нужен один процесс на токен. При наличии webhook переключение способа доставки нужно согласовать перед запуском.

Бот читает описания и исходные демо-тарифы из [общего каталога](../content/en.json) при запуске.


### Восстановление демо-заявки

При подключённой CRM незавершённая заявка сохраняется локально. `/resume` восстанавливает её после перезапуска; `/discard` позволяет после подтверждения удалить локальный черновик. Если ответ CRM был потерян, повтор использует тот же ключ. Удаление черновика не удаляет уже полученную CRM заявку. Хранилище `bot/data/` исключено из Git, содержит потенциально идентифицирующий хеш Telegram ID и не имеет автоматического срока удаления. [Подробнее о восстановлении](../docs/OUTBOX-PLAN.md)

При подключённой CRM подбор поездки в боте использует серверный демо-тариф и наличие по датам. Путь CRM должен указывать на тот же сервер, который обслуживает /api/guest/quotes/. Новый черновик сохраняет полученный тариф. Без CRM бот продолжает показывать расчёт по локальному каталогу.
